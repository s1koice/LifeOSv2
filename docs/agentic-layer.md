# Agentic layer: аудит и архитектура

## Что было до внедрения

NEXUS уже содержал рабочую доменную модель: задачи, проекты, цели, привычки и их историю, сферы жизни, входящие, PARA-ресурсы, финансы, здоровье, календарь, журнал, фокус-сессии, еженедельный обзор и геймификацию. Данные сохранялись одним совместимым JSON-снимком в `localStorage` и в защищённой строке Supabase `nexus_pin_state`.

AI уже умел создавать и изменять основные сущности через Responses API, а также анализировать банковские файлы. Недостающим был не ещё один чат, а единый слой, который собирает контекст, отличает анализ от действия, хранит только значимую память и объясняет каждое предлагаемое изменение.

## Решение

Существующая модель не переписана. Поверх неё добавлен один **Daily Operator** и пять переиспользуемых навыков:

- утренний бриф;
- вечерний разбор;
- обзор недели;
- финансовый обзор;
- обзор целей.

Все навыки используют один `AgenticContext`, одну память и один журнал действий. Правила работают локально даже без API-ключа. Провайдер OpenAI подключается через отдельный интерфейс и улучшает анализ, но не выполняет изменения самостоятельно.

## Поток данных

```text
задачи / цели / проекты / привычки / здоровье / финансы / журнал
                              ↓
                       AgenticContext
                              ↓
                   Daily Operator + skills
                              ↓
          внимание · TOP 3 · инсайт · предложение
                              ↓
                   принять / отклонить / спросить
                              ↓
               существующие функции изменения NEXUS
```

## Новые данные

Новые поля являются необязательными частями прежнего JSON-снимка:

- `agentMemory` — профильная, текущая, эпизодическая и паттерн-память;
- `agentSuggestions` — предложения и их статус;
- `agentActionLog` — анализы, предложения, исполнения, отклонения и решения по памяти;
- `agentLinks` — явные связи Task → Project → Goal и Habit → Health;
- `routineRuns` — история запусков навыков;
- `operatorBrief` — последний дневной бриф.

Миграция базы не нужна: старый снимок открывается с пустыми значениями новых полей. Откат также безопасен — старые версии приложения проигнорируют неизвестные поля.

## Память и приватность

- AI получает только структурированный контекст NEXUS, необходимый выбранному навыку.
- Кандидат в долгосрочную память появляется только при достаточном количестве наблюдений.
- Пользователь отдельно решает «Сохранить» или «Не запоминать».
- Корреляции маркируются как возможные закономерности и содержат число наблюдений и уровень уверенности.
- Секретный серверный ключ OpenAI не попадает в браузер. BYOK остаётся необязательным локальным режимом.

## Контроль действий

Daily Operator работает по контракту:

1. анализирует;
2. показывает основание;
3. предлагает одно конкретное действие;
4. ждёт решения пользователя;
5. только после принятия вызывает существующую функцию NEXUS;
6. записывает результат в журнал действий AI.

Скрытых внешних действий, автоплатежей, отправки сообщений или необратимых изменений нет. Уже существующий чат-ассистент по-прежнему может выполнять явные команды пользователя и сохраняет снимок для отмены.

## Совместимость

- существующие разделы и форматы сущностей сохранены;
- Supabase-архитектура сохранена, облачная синхронизация работает без PIN-входа;
- локальный fallback сохранён;
- OpenAI заменяем через `AgenticProvider`;
- без `OPENAI_API_KEY` используется детерминированный rules-provider;
- второстепенные блоки главной не удалены, а перенесены в раскрываемый раздел.
